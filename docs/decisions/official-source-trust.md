# 결정: 기업 조사 출처의 신뢰 기준

- 날짜: 2026-10-20
- 범위: ESSAY-10 조사 역할 구현·검증 완료. 최종 결과와 실패 이력은 [검증 보고서](../qa-evidence/assignment/research/verification.md)에 있다.
- 사용자 선택: 초기 공식 출처 지원 기업은 네이버·카카오·OpenAI·Anthropic이다. 검토한 정확한 공식/채용 호스트와 회사 범위만 등록한다.
- 근거: [PRD 자료 규칙](../PRD_V2.md), [기술 설계](../TECH_DESIGN_V2.md), [이번 완료 기준](../qa-evidence/assignment/research/acceptance.md).

모델이 반환한 URL·official 표시·검색 요약은 후보 자료다. HTTPS 인증서, 기업명과 비슷한 도메인, 페이지 속 기업명이나 Organization JSON-LD만으로 기업 소유권을 자동 증명할 수 없다. 출처 신뢰의 출발점은 운영자가 출처를 확인해 등록한 기업별 정확한 이름/별칭·공식 HTTPS 호스트다.

초기 등록 대상은 사용자 선택에 따라 네이버·카카오·OpenAI·Anthropic이다. 이 목록은 검색 결과를 만드는 고정 데이터가 아니라 공식 출처를 승격할 수 있는 신뢰 경계다. 실제 본문과 링크는 요청할 때 읽어 확인한다. 등록되지 않은 기업은 공식성을 추정하지 않고 명시된 사용자 공고 본문을 활용하거나 기업/공고 보완을 요청한다. 지원 범위를 넓히려면 기업별 공식 주소의 근거와 확인 날짜를 검토해 목록을 추가해야 한다.

직접 확인한 운영 근거:

- [OpenAI 공식 채용](https://openai.com/careers/)에서 [공식 채용 검색](https://openai.com/careers/search/)으로 연결된다.
- [Anthropic 공식 채용](https://www.anthropic.com/careers)에서 [채용 목록](https://www.anthropic.com/careers/jobs)과 개별 공고로 연결된다.
- [네이버 공식 기업 사이트](https://www.navercorp.com/main)에서 [공식 채용](https://recruit.navercorp.com/)으로 연결된다. 공고의 JobPosting/채용 회사가 NAVER인지 확인하며 전역 회사 필터·로고를 증거로 쓰지 않는다. NAVER Cloud·LABS·WEBTOON 등 계열사는 별개다.
- [카카오 공식 기업 사이트](https://www.kakaocorp.com/page/)에서 [공식 채용](https://careers.kakao.com/index)으로 연결된다. 같은 사이트의 카카오페이·게임즈 등 계열사를 카카오로 간주하지 않는다. 직접 읽기가 JavaScript 안내만 반환하면 검색 요약으로 본문을 대체하지 않고 보완을 요청한다.
- 외부 채용 플랫폼은 호스트 전체를 승인하지 않는다. 실제 읽은 공식 페이지의 정확한 공고 링크와 일치해야 하며 다른 기업의 tenant·다른 공고·신뢰 밖으로의 리다이렉트는 그 승인에 포함하지 않는다.

공식 source는 신뢰된 기업 관계와 실제 읽은 본문의 인용을 함께 확인한다. 직무 요건은 확인된 직무 공고와 실제 요건 구역에 연결돼야 하며, 페이지 다른 위치에 직무 이름이 있다는 사실만으로 일반 인재상을 직무 요건으로 바꾸지 않는다. 인용은 원문과 대조하고 없는 ID·상충·불명확한 관계는 보수적으로 제외하거나 보완 요청으로 돌린다. 직무 요구가 없으면 진행하지 않으며 인재상만 없으면 생략한다.

공식 직무 공고는 실제 페이지의 사용 가능한 JobPosting JSON-LD가 정확히 하나여야 한다. 네이버의 검토한 상세 경로는 단일 공고 카드 제목을 같은 레코드와 묶고 그 카드의 업무/필수 기술 구역에 있는 원문을 서버가 발췌한다. 구역 하나를 선택하는 보수적 지원이며 모든 요건의 수집을 보장하지 않는다. 다른 형식은 기존 엄격한 인용 검사 또는 보완으로 끝난다. 직무 제목과 고용주는 같은 레코드로 묶어 검증한다. 특히 네이버·카카오 공용 채용 사이트에서는 해당 레코드의 고용주가 정확히 요청 기업이어야 한다. 일반 h1·문화 글·전역 회사 필터를 공고 증거로 사용하지 않는다. 여러 공고가 있는 목록, 표준 공고 자료가 없는 페이지, 접근 거부나 JavaScript만으로 표시되는 자료는 사용자 공고 본문을 요청할 수 있다. 등록 기업이라고 모든 페이지 형식을 지원하는 것은 아니다.

사용자가 붙인 공고는 서버가 실제 입력 본문을 `user_provided` source로 만든다. 모델이 만든 구절을 사용자 원문으로 가장하지 않는다. 입력 기업·직무와 연결되지 않거나 원문에 없는 구절은 채택하지 않는다. 사용자 제공 표시는 공식 기업 확인을 뜻하지 않는다. 짧은 인용은 같은 LF 줄의 요청 직무명·요건 표시·콜론 뒤 값 전체와 일치할 때만 추가 수용하며, 부정이나 조건을 잘라내지 않는다. 사용자 공백은 그대로 보존한다.

네트워크 경계는 [OWASP SSRF 지침](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)을 참고한다. 각 HTTP(S) 요청과 redirect에서 공개 IP를 확인하고, 실제 연결도 확인한 숫자 IP로 고정한다. 원래 호스트의 Host/TLS SNI·인증서 검증을 유지하며 proxy 환경·자동 재시도를 사용하지 않는다. 직접 읽기3회·페이지1MiB·정리 텍스트 합계12000코드포인트와 기존 조사45초를 공유한다. 이 수치를 hosted 검색 내부의 검색어·페이지 수 통제로 해석하지 않는다.

이 검증은 출처 관계와 인용의 추적 가능성을 강화한다. 모든 의미적 주장·공고의 현재 모집 여부·사용자 정보의 진실성까지 증명하는 것은 아니다. 실제 모델 품질과 새 자기소개서 사실성 승인은 ESSAY-17에서 별도로 수행한다.

상충 검사는 명시된 모호/상충 보고와 제한된 수치·부정 표현 반례를 다루며 일반 의미 분석기가 아니다. 지시문 형태 검사도 보조 수단이고 정상적인 보안 직무 설명을 보수적으로 제외할 수 있다. 실제 보호 경계는 입력/도구/예산 분리, 원문 대조, 운영자 출처 목록과 제한된 직접 읽기다. 알려진 단어 검사만으로 모든 프롬프트 삽입을 탐지했다고 표현하지 않는다.
