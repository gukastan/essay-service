## ESSAY-9 완료 기록 — 2026-10-19

사용자가 이번 개발을 공통 기반 구현·검증까지로 한정했다. 계약·LangGraph 상태·공유 예산·모델/검색 어댑터를 세 개발 에이전트가 분담하고 메인이 통합 검사와 실제 HTTP 확인을 수행했다.

- 전체 자동 테스트 156개 통과(기존 76개 포함), 유료 연결 테스트 1개는 기본 실행에서 의도적으로 건너뜀. 타입 검사·lint·production build 통과.
- 실제 LangGraph 패키지로 병렬 합류 순서·요청 상태 격리·수정 상태 제한을 검사했다. 제품 네 역할의 프롬프트와 전체 그래프는 아직 구현하지 않았다.
- OpenAI 모델/내장 검색 실연결 총 4회 성공. 마지막은 제품 어댑터를 통해 서버의 `max_tool_calls=2`, 실제 보고 도구1회, 예약2회·모델1회, 4.7초를 확인했다.
- 내장 내부 검색어·페이지 수를 독립 통제하지 못하는 점을 확인했고, 사용자가 기존 키와 내장 도구 횟수 기준을 승인했다. 직접 주입 검색2/페이지3과 구분한다.
- 별도 운영 빌드에서 홈200, v1 잘못된 입력400, 아직 없는 v2 경로404 확인. 기존 개발 서버와 원본 5개 샘플·v1 QA를 보존했다.

명령·코드 해시·실연결 결과·발견 및 수정 이력·미검증 범위: [상세 검증 보고서](qa-evidence/v2/essay-9/verification.md).

## 실제 모델·자료 — V2-09

기존 5개 원본 입력(일반 경험 2개, 정보 부족, 긴 경험, 없는 성과 추가 요구)을 수정하지 않는다.

1. 원본 5개를 실제 v2 전체 흐름에 넣는다. 가상 기업이거나 직무 근거가 없으면 needs_input이 올바른 결과다.
2. 작성 품질 회귀는 같은 네 입력에 별도로 표시된 시험용 공고 본문을 선택 자료로 추가해 수행한다. 공식 기업 정보가 아닌 user_provided 시험자료임을 명시한다. 정보 부족 사례는 보완으로 종료해야 한다.
3. 최소 실제 기업 2곳의 공식 자료로 별도 사례를 구성한다. 공식 공고 성공, 인재상만 있고 직무 근거 부족, 기업 식별 모호, 접근 불가를 포함한다. 실제 검색·페이지·모델을 사용했는지 각각 기록한다.
4. 모든 생성 초안에서 사용자 사실 추가, 기업 주장 출처, 문항 답변, 직무 연결, 원문 문장 보존, 길이를 사람이 대조한다.
5. 실패하면 문제·수정·같은 사례의 재검증 결과를 보존한다. 성공 기록으로 이전 실패를 덮어쓰지 않는다.

모의 조사 자료를 사용한 결과를 실제 공식 출처 검증이라고 보고하지 않는다. 가상 회사 사례에서 조사가 실패한 것을 억지로 정상 생성으로 바꾸지 않는다.

## 실제 브라우저와 완료

QA 환경에서 v2를 활성화해 입력 → 생성 → 출처와 연결 이유 확인 → 경험 비교 → 편집 → 복사를 검증한다. 실패/보완 후 입력 보존과 편집 후 생성 당시 검토 표시도 확인한다.

증거에는 입력/선택 자료, 실제 출처와 확인일, 모델/의존성 버전, 출력, 판정, 단계별 지연·토큰·호출/검색 횟수 및 가능한 비용을 남긴다. API 키를 저장하지 않는다. 표본 평균/범위를 기록하고 소수 사례를 근거로 일반적인 성능 개선을 주장하지 않는다.

작성자에게 읽을 수 있는 최종 보고서를 제공한다. 작성자가 사실성을 확인하기 전에는 V2-09와 에픽을 완료 처리하지 않는다. 승인 시점·실제 Jira 상태·기능 설정 전환을 기록한 후 README와 시연 절차를 갱신한다.
