## ESSAY-9 완료 기록 — 2026-10-19

사용자가 이번 개발을 공통 기반 구현·검증까지로 한정했다. 계약·LangGraph 상태·공유 예산·모델/검색 어댑터를 세 개발 에이전트가 분담하고 메인이 통합 검사와 실제 HTTP 확인을 수행했다.

- 전체 자동 테스트 156개 통과(기존 76개 포함), 유료 연결 테스트 1개는 기본 실행에서 의도적으로 건너뜀. 타입 검사·lint·production build 통과.
- 실제 LangGraph 패키지로 병렬 합류 순서·요청 상태 격리·수정 상태 제한을 검사했다. 제품 네 역할의 프롬프트와 전체 그래프는 아직 구현하지 않았다.
- OpenAI 모델/내장 검색 실연결 총 4회 성공. 마지막은 제품 어댑터를 통해 서버의 `max_tool_calls=2`, 실제 보고 도구1회, 예약2회·모델1회, 4.7초를 확인했다.
- 내장 내부 검색어·페이지 수를 독립 통제하지 못하는 점을 확인했고, 사용자가 기존 키와 내장 도구 횟수 기준을 승인했다. 직접 주입 검색2/페이지3과 구분한다.
- 별도 운영 빌드에서 홈200, v1 잘못된 입력400, 아직 없는 v2 경로404 확인. 기존 개발 서버와 원본 5개 샘플·v1 QA를 보존했다.

## ESSAY-18 완료 기록 — 2026-10-20

OMO 두 담당자가 원본 보존/실행과 API/MCP 흐름을 분담했고 리더가 실제 브라우저와 기존 코드 보존을 확인했다. 원본 소스·문서·자산 46개를 assignment/에 복사했고 실행 코드는 수정하지 않았다. Mac의 별도 Python 3.11.15 환경에서 실제 FastAPI·LangGraph·MCP·Vue를 실행했다.

- 실행 환경 점검 13개, API/SSE 25개, 독립 stdio MCP 8개, 브라우저 5개 통과. 총합은 검사 항목 수이며 제품 단위 테스트 수가 아니다.
- 일반 대화, 계획·게이트·자료 조회·추가 매뉴얼 조회, 첫 초안 반려와 두 번째 초안 통과를 확인했다. analysis 노드는 진입했지만 FakeLLM에서는 AnalysisSkipped였다.
- 원본의 첫 도구 timeout은 의도적인 오류 주입이고 모니터링은 JSON fixture다. 실제 모델·검색·운영 모니터링·분석 모델·정량 병렬 성능은 검증하지 않았다.
- 실제 화면의 fake/실모델 혼합 문구와 반려 초안 노출, run.sh 누락을 후속 전환에 인계한다. 기존 Next.js 코드는 해시로 보존 여부를 확인했으며 Node 회귀를 재실행하지 않았다.

설치·명령·원본/기존 코드 해시·입력과 실제 결과·화면·예외·종료 기록은 [검증 보고서](qa-evidence/assignment/baseline/verification.md)에 연결했다. 이 완료는 원본 실행 기준선에 한정하며 ESSAY-19 이후의 Python 계약·모델/검색·자기소개서 품질을 인증하지 않는다.

## ESSAY-19 완료 기록 — 2026-10-20

Pydantic 계약·실제 LangGraph 상태·원자 예산·구조화 모델/MCP 후보 조사·lifespan·LF/코드 포인트·run.sh를 구현했다. Python131개 통과/유료1개 기본 skip, JS12개, 실제 Vue 기반5개, 실행5개, 설치 중단3개가 통과했다. 기반/테스트32개 파일의 타입 진단0, Ruff·포맷 검사 통과.

기존 gpt-5.6-terra로 구조화 출력1회(1.680초)와 실제 stdio MCP 검색1회(11.300초)를 별도 실행했다. 두 스키마 통과, hosted 실제 보고량1회/예약량2회, 자동 재시도0이다. 공개 기업·직무만 전송했고 키·전체 프롬프트·제공자 본문은 저장하지 않았다. 이는 후보 검색 호환 검사이며 공식성·자기소개서 품질 검증은 아니다.

원본46개와 허용된 변경을 제외한 기존441개 파일은 해시상 불변이다. 잘못된 공고 타입/URL 포트/근거 offset, malformed SDK 응답, MCP timeout 후 추가 호출 차단, stdio 자식 정리의 실패→수정 기록을 보존했다. [상세 보고서](qa-evidence/assignment/foundation/verification.md)에 실제 명령·결과·한계를 연결했다. /api/drafts와 새 Vue 제품 화면은 미구현이며 ESSAY-10~17·20은 할 일로 유지한다.

## 실제 모델·자료 검증

1. 기존5개 원본 입력을 변경하지 않고 새 서비스에 넣는다. 가상 기업/직무 근거 부족은 needs_input이 정답이다.
2. 작성 품질 회귀는 같은 네 입력에 별도로 표시한 user_provided 시험 공고를 추가해 실행한다. 공식 자료로 가장하지 않으며 정보 부족 경험은 계속 보완 요청이어야 한다.
3. 실제 기업 최소2곳의 자료를 별도로 확인한다. 공식 공고 성공·인재상만 있고 직무 근거 부족·기업 모호·접근 불가를 포함한다.
4. 원문 사실 보존·개인 사실 추가0건·회사 주장 출처·문항 충족·직무 연결·분량을 사람이 대조한다.
5. 실패→수정→같은사례 재검증의 원본 응답과 판단을 각각 남긴다.

각 사례에는 ID·기능·입력/선택자료·기대결과·실제응답·판정·실행시각·코드 커밋·환경/모델 버전·출처/확인일·역할별지연·토큰·모델 호출·hosted 예약/보고량·증거 경로를 기록한다. 과금 자료가 없으면 실제 비용 미확인으로 남긴다. 내부 검색어/페이지/바이트를 독립 측정한 것처럼 보고하지 않는다.

## 화면과 오류·예외 증거

실제 Vue에서 입력→생성→근거 확인→원문 비교→편집→복사를 확인한다. 보완/오류 후 입력 유지, 편집 이후 생성 당시 검토 배지, 모바일 화면도 캡처한다.

키 누락·MCP 단절·모델/검색 timeout·품질 실패는 통제된 오류 주입으로 재현할 수 있다. 이 경우 주입 방법과 실제로 통과한 계층을 표시한다. 모의 모델 응답이 실제 생성 결과로 표시되거나 장애가 실서비스에서 자연 발생한 것처럼 보고되지 않도록 한다. 비밀·개인정보가 포함되지 않은 시험자료를 사용한다.
