## Final tightening (2026-10-20)
- ResearchSuccess contains only `status`, verified `result`, `tool_calls_reported`, `usage`; raw candidate report is not exposed.
- FetchedPage has additional default-empty `job_titles` and `employers` tuples. Parser extracts actual visible h1 or JSON-LD JobPosting.title, and JobPosting.hiringOrganization.name. Official job evidence requires role in actual posting title and literal role-bearing requirement quote. Quote needs explicit requirements/responsibilities/qualifications/자격/요건/담당 marker, not bare experience/culture. Own-host source path requires job/jobs/채용/rcrt, or careers path with role slug. Unknown layouts fail closed.
- Added NAVER/네이버 and Kakao/카카오 maintained roots (see domestic-trust.md primary evidence); shared sites additionally require exact posting employer (require_employer=True), never body/footer/filter substring. Affiliates not included.
- Text aggregate cap is checked before page enters cache. Every external ATS success retains fetched official root source and attaches its ID to job source references. All dates are server fetch time; model publication/closing dates dropped.
- Literal company and role matching uses Unicode word boundaries. Critical candidate ambiguity/conflict reports block; exact mismatched resolved company blocks. Simple same-frame numeric/polarity contradictions are detected deterministically (source_conflicts); semantic contradiction completeness is NOT claimed. Optional disputed company facts are discarded.
- API-key references alone are not injection. Known instruction phrases excluded, and all remaining data stays inert regardless of phrase detection.
- Public IPv6 transition ranges rejected; explicit port policy80/443, redirects charged, HTTP timeout stops request budget. Internal page counts remain separate from hosted internals.

## Final paired-posting correction (supersedes h1/title tuple design)
`FetchedPage.postings: tuple[agent.source_structured.Posting,...] = ()` replaces independent `job_titles`/`employers`. Each frozen Posting keeps title and optional hiringOrganization employer paired. Only actual JSON-LD JobPosting entries populate this field; generic h1 remains visible text only. Official job identity requires exactly one JobPosting entry, its title matching requested role, and its own exact employer where require_employer=True. Multi-posting/unsupported pages fail closed even if separate entries collectively mention the target employer and role. Existing requirement quote/provenance/HTTP rules are unchanged.

## Original-language quotation correction
Official fetched text and candidate excerpts/facts/jobs use identical whitespace-run canonicalization (`" ".join(value.split())`). Every other character is preserved: no translation, case folding, punctuation removal, Markdown stripping or fuzzy quote matching. Admitted official excerpts must be contiguous in fetched cleaned text; admitted official jobs/facts must be contiguous in referenced admitted excerpts. Raw user-provided source text and exact user quote remain unchanged; a valid raw user quote takes precedence over official normalization. Prompt explicitly requests original-language visible-page quotations and own-source substring consistency. Single paired JobPosting and HTTP trust constraints are unchanged.

## NAVER fetched-section proof
`FetchedPage.requirement_sections: tuple[RequirementSection,...] = ()`, where frozen RequirementSection contains `posting_title`, `heading`, `text`. New extraction is limited to exact recruit.navercorp.com /rcrt/view.do, one div.card_wrap, h4.card_title, nested div.detail_box and h4.detail_title exactly What You'll Do or Required Skills. It does not infer sections from global headings or require a detail_wrap ancestor. Each extracted section must also occur in bounded cleaned page text. Same single JSON-LD posting identity/employer remains mandatory, and card title must equal that posting title after whitespace canonicalization.
For this proof path only, an associated candidate job quote must occur literally (whitespace canonicalization only) inside one actual fetched section; role/heading need not repeat in each bullet. Server returns that section as source excerpt using the candidate's same source ID and fetched URL/check time. Translated model excerpt is not promoted: it is replaced by actual fetched proof only when an associated literal requirement matches. Quotes cannot span sections, and changed/translated/Markdown-decorated bullets still fail. Other sites retain prior exact-excerpt proof behavior. Only one matching section is selected per candidate source; this may omit valid requirements from other sections but does not invent or combine them.

Final prompt aligned with section API: NAVER duty/skill bullets are separate original-language job requirements; role/title and heading need not repeat in each bullet because paired posting/card proves identity. Excerpt is original requirement section containing bullets, not whole-page employment metadata. No verifier/API behavior change in this final prompt-only edit.
