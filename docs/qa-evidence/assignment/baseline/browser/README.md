5개 검사가 통과했다. 리더가 초기 화면과 장애 결과 이미지를 직접 확인했다. 실행 시각과 DOM 관찰은 [result.json](result.json), 조작 직전 상태는 각 snapshot JSON에 있다. 전체 프롬프트 패널을 열지 않았다.

원본 화면에는 fake 모드도 `실모델`로 표시하는 문구가 있고, 반려된 첫 초안 `재시작하면 됩니다.`도 대화에 남는다. 이는 보존한 원본의 동작이며 실제 모델 품질이나 새 자기소개서 UI의 통과를 뜻하지 않는다. ESSAY-15에서 새 화면을 만들 때 올바른 실행 모드와 최종 결과를 구분해야 한다.

재현: 원본 fake/v2 API와 화면 서버를 시작한 뒤 저장소에서 `node docs/qa-evidence/assignment/baseline/browser/run-browser.mjs`를 실행한다. 검증 스크립트는 로컬 설치된 omo 브라우저 도구를 사용한다. 검사 종료 시 자신이 띄운 브라우저를 닫고 임시 프로필을 삭제한다.

첫 제한 환경 시도는 브라우저 시작 단계에서 응답이 없어 해당 Node 프로세스만 종료했다. 허용된 환경에서 같은 스크립트를 재실행해 통과했으며 애플리케이션 코드 수정은 없었다. 실패한 첫 시도를 제품 오류나 통과한 실행으로 세지 않았다.
