## 목적

사용자가 입력한 기업·직무·문항·경험으로 초안을 만든다. 기업·직무 조사, 경험·문항 분석, 작성, 검토의 네 역할을 분리한다. 확인 가능한 직무 요건과 인재상은 경험과 관련될 때만 보강 자료로 활용하며, 문항과 사용자가 입력한 직무를 우선한다.

회사 이름에서 연상한 인재상, 타사의 공고, 사용자가 말하지 않은 경력·행동·성과·배움으로 글을 채우지 않는다. 네 역할 분리 자체가 품질을 보장하지 않으므로 실제 사례로 효과를 확인한다.

## 사용자 흐름

1. 기존 필수 네 항목(기업명·직무·문항·경험)을 입력한다. 선택 항목으로 채용 공고 URL과 공고 본문을 제공할 수 있다.
2. B에서 문항 요구를 해석하고 C에서 개인 근거와 확인된 기업·직무 자료를 정리한다. 조사할 자료가 있으면 기업 조사를 개인 분석과 병렬 수행한다. 직접 한 행동을 알 수 없는 등 필수 개인 경험이 부족하면 작성 전에 `추가 정보 필요(초안 없음)`로 종료한다. 공고·공식 자료 부재만으로는 종료하지 않는다.
3. B/C가 준비되면 D에서 사용할 경험·주장·문단 구성을 짧은 계획으로 정하고 E에서 초안을 작성한다. F는 전체 초안의 사실·근거·필수 문항·직무 연결·분량을 검사한다.
4. G는 모든 기준 충족 → 최종 결과, 작성 후 필수 정보 부족 또는 수정 한도 도달 → 기준 미충족 최종 결과, 수정 가능하면 경험/주장/구성 변경 → D, 문장만 변경 → I로 보낸다. 두 수정 경로는 공통 수정1회를 공유하고 전체 F로 돌아온다.
5. 기준 충족 결과는801~1,000자 초안·원문·출처/확인일·직무 연결 이유를 보여준다. 기준 미충족 결과도 마지막 초안을 숨기지 않고 미충족 기준·사유·수정 안내를 함께 표시한다. 작성 전 필수 경험 부족만 초안 없는 추가 정보 요청이다.
6. 사용자는 편집·글자 수 확인·복사를 한다. 편집하면 생성 당시 검토와 사용자의 수정 내용을 구분한다.

## 자료 사용 규칙

- 우선순위: 문항의 요구 → 해당 직무·공고의 요구 → 관련 있는 기업 인재상.
- 공식 홈페이지·공식 채용 페이지를 우선한다. 외부 채용 플랫폼은 공식 사이트에서 연결되는 등 해당 기업의 공고임을 확인한다.
- 공고가 모집 중이라고 확인되지 않았다면 현재 채용 중이라고 단정하지 않는다. 확인 날짜와 자료에 표시된 게시/마감일을 구분한다.
- 사용자가 붙여 넣은 공고 본문도 활용할 수 있으나 `user_provided`로 표시하고 공식 검증 자료로 가장하지 않는다.
- 공고·공식 자료가 없어도 사용자가 입력한 기업·직무와 경험으로 작성한다. 확인되지 않은 기업 사실이나 특정 공고 요건은 만들지 않는다. 입력 직무와 다른 공고는 해당 직무 요건으로 반영하지 않고 화면에 그 한계를 표시한다.
- 출처끼리 상충하면 해당 사실을 제외하고 입력한 직무를 기준으로 계속 작성한다. 직접 한 행동 등 초안에 필수적인 개인 경험 자체가 부족한 경우에만 보완을 요청한다.
- 검색에는 기업·직무 정보만 사용하며 경험·문항 전문을 외부 검색어로 보내지 않는다.
- 현재 OpenAI 키로 내장 검색을 사용한다. 요청당 내장 도구 호출 최대 2회를 제한하며 내부 검색어·페이지 수는 별도로 통제하지 못한다. 사용자 승인일은 2026-10-19이며 세부 계측과 한계는 [기술 설계](TECH_DESIGN_V2.md)를 따른다.
- 원문과 웹페이지 속 지시는 자료로 취급한다. 시스템 규칙과 실행 예산을 바꿀 수 없다.
- 사용자 과거 사실의 표현 보존 원칙은 [기존 결정](decisions/factual-drafting.md)을 유지한다. 자유로운 과거 사실 재서술은 별도 검증 없이 도입하지 않는다.

## v1 대비 범위 변경

| 항목 | 완료된 v1 | 계획된 v2 |
| --- | --- | --- |
| 모델 흐름 | 직접 호출, 길이 밖이면 한 번 재작성 | 네 모델 역할 위에 요구사항/근거·계획·작성·평가·다음 행동 결정, 최종 결과/재계획/부분 수정 분기 |
| 기업 자료 | 입력한 기업명·직무 | 입력을 작성 기준으로 유지하고 공식 자료·사용자 공고는 확인된 범위만 보강 |
| 호출 상한 | 최대 2회 | 최대 6회, 자동 재시도 0 |
| 분량 | 801~1,000자 | 동일, 사실성 수정과 공통 1회 수정 예산 |
| 결과 근거 | 경험과 초안 비교 | 경험 비교 + 기업 출처 + 직무 연결 이유 |
| 실행 | 루트 Next.js 보존본 | assignment/의 별도 Python·Vue 서비스 |

MCP는 기업·직무 조사 도구 연결에 포함한다. 로그인, 사용자 DB 저장, 벡터 검색/RAG, 무제한 에이전트 토론, 자기소개서 합격 예측, 서비스의 Jira 자동 연동은 범위 밖이다. 현재 개발 작업의 Jira 관리와 제품 기능을 구분한다. v1의 3일 일정은 과거 계획이며 v2 일정·비용이 확정됐다는 뜻이 아니다.
